============================================

变化（任务模式下"避雨/继续任务"得分高，保护模式下"立即返航"

八、P0 修复：speed metric 未接入 UART（2026-10-13）
============================================
说明：本节只记录已做的事，不含待办。

用户复核发现 P0 bug：
  `speed`（飞行速度）metric 没有接进任何一路 UART 通道。
  serial_io.CHANNELS 全部 5 路 metrics 列表里都无 "speed"，
  DEFAULTS 里也无 "speed"。

后果链：
  1. trigger.read_metrics_from_io() 从缓存读不到 speed
  2. ai_main._build_command() 里 metrics.get("speed", 0.0) 永远拿到 0.0
  3. cruise.speed_track(目标5.0, 当前0.0, dt) 算出差速 5.0
     -> kp*5=6.0 -> 限幅后 throttle_delta=1.0（满油门）
  4. 6 个场景里 5 个都带着 throttle_delta=1.0
     唯独低电量场景因 battery_issue 属 fatal 被跳过巡航计算，输出 {}
  5. 真实上机时会让定速巡航持续打满油门，属危险指令

修复内容（3 处改动）：
  a. serial_io.py CHANNELS["uart1"]["metrics"] 补上 "speed"
     （飞控 MAVLink 的 GLOBAL_POSITION_INT 提供 vx/vy/vz，合成 speed）
  b. serial_io.py DEFAULTS 补上 "speed": 5.0
  c. serial_io.py SerialIO.start() 加 demo_mode 参数；
     _pump() 在 demo_mode 下不生成默认帧（由 _inject_metrics 控制），
     避免演示时注入值被后台 20Hz pump 线程冲掉

附带修复（cosmetic）：
  - ai_main.main() 打印"5 路最新帧"时改从 _cache 尾读
    （demo 模式下 _latest 为空，_cache 才有注入的帧）
  - ai_main.main() 先 _inject_metrics(DEFAULT_METRICS) 再打印

import ai_main; ai_main.main()"）

     让正常飞完到达终点时 battery_v 跌到 12.4V（< BATTERY_CRIT_V=14.4V），
     每次正常飞行都误触发 battery_issue 自身事件、立即迫降、任务终止。
   - 新公式 flight_frac*(BATTERY_MIN_TAKEOFF_V-BATTERY_WARN_V)，
     正常飞行终点电量落在 BATTERY_WARN_V=15.0V（告警线但高于紧急线），
     只有低电量事件显式注入时（battery_v=BATTERY_CRIT_V-0.5=13.9V）才真正触发。
   - battery_pct 同步从 0.85 衰减系数改为 0.45，正常飞完约 55%（旧 15%）。
   - import math 移到文件顶部（消除循环内局部 import，PEP8 合规）。

2. P0-2 gimbal_fault / payload_fault trigger 规则补全（trigger.py）
   - 旧版模拟器会注入 gimbal_pitch / payload_fault 事件，
     但 trigger.py 没有对应规则，AI 永远检测不到（死事件）。
   - 新增两条 TRIGGER_RULES：
       ("gimbal_pitch", "gimbal_fault",
          abs(v) > T.GIMBAL_PITCH_MAX_DEG)   阈值 80°
       ("payload_fault_flag", "payload_fault",
          bool(v))                            载荷自检标志
   - thresholds.py 新增第 12 节：GIMBAL_PITCH_MAX_DEG=80、
     PAYLOAD_FAULT_FLAG_DEFAULT=0。
   - serial_io.py：CHANNELS[uart4].metrics 加入 payload_fault_flag，
     DEFAULTS / UNITS 同步补全。
   - ai_main.py：DEFAULT_METRICS 加入 payload_fault_flag=0。
   - simulate.py：payload_fault 事件改为注入 payload_fault_flag=1，
     gimbal_pitch 随机范围 60~80°（< GIMBAL_PITCH_MAX_DEG，不触发 gimbal_fault，
     避免与 payload_fault 混淆；gimbal_fault 事件仍单独注入 85~95°）。

3. P0-3 路径去硬编码
   - simulate.py：--out 默认值从硬编码 D:\123\sim_output.xlsx 改为
     基于 __file__ 相对路径（项目根目录下 sim_output.xlsx）。
   - run_sim.py：注释 D:\123 改为"项目根目录 (123/)"。
   - server.py：开发模式注释 D:\12\123 改为 _ROOT/123 相对说明；
     实际代码原本就用 _ROOT/123 相对路径（仅注释残留，已修正）。

4. P1-1 simulate.py 抽公共循环

     闭环积分、AI.tick、时间轴记录）。
   - 抽出 _build_sim_loop(events) 公共方法，run() 与 run_stdout() 各自只剩

     {"t", "pos":[x,y,z], "yaw"}，供 server.py 3D 动画消费。

5. P1-2 分类器关键词去重（analyzer/classifier.py）
   - 13 个 anomaly_type 的 RULES 关键词列表存在重复词
     （如 motor_failure "马达"×2、prop_break "prop strike"/"prop"×2、
     payload_fault "载荷 故障"/"喷洒 故障" 各×2、signal_loss "telemetry"×2 等）。
   - 逐块去重（保持首次出现顺序），共删 35 个重复关键词，
     13 个规则块全部无重复。
   - 不影响分类准确率（去重只是删除冗余，首条命中词不变）。

6. P1-3 decision.py xlsx 加载失败加 warning
   - _load_matrix() 原先 except: pass 静默吞掉 openpyxl 加载失败，
     导致 P/T 矩阵为空时用默认值但无任何提示。
   - 改为：文件不存在 → warnings.warn 提示路径不存在；
     加载异常 → warnings.warn 提示失败原因（ModuleNotFoundError / 其他）。
   - 同时把 from openpyxl import load_workbook 移到 try 块内，
     避免 openpyxl 未安装时 import 就抛 ModuleNotFoundError 中断整个 decision.py。
   - 附带修复（验证中发现的原有 bug）：
       _w_compute_P(anomaly) 调用缺少 crash/success 参数
       （weight_base.compute_P 签名是 (an_type, crash, success)）。
       机载运行时无历史数据，传 0,0 退化为纯先验 P_prior。

7. P1-4 server.py position_seq 改读模拟器真实轨迹
   - 旧版 _parse_report 用 home + t*0.01 线性漂移生成 position_seq
     （与模拟器闭环积分的真实位置完全无关）。
   - 新版 _run_sim 捕获 sim._pos_history（P1-1 新增），
     传给 _parse_report 作为 pos_history 参数。
   - pos_seq 优先用 _pos_history（NED 坐标 → 近似经纬度偏移，
     lat += x/111000, lon += y/(111000*cos(lat))，alt = home_alt - z）；
     若 pos_history 为空（旧版 simulate.py 兼容）回退到旧版 t*0.01 漂移。
   - 新增 "yaw" 字段供 3D 模型机头朝向。
