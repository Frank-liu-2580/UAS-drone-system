# 无人机飞行模拟 · 使用说明

> 本目录 `123/drone_sim` 是"机载影子 AI 飞行模拟"。它驱动 `drone_ai` 包
> 跑一次完整飞行（起飞 → 巡航 → 途中随机异常事件 → 安全降落），把 AI 的
> 决策全程记录成一份"事件时间轴"报告。
>
> **双击运行：`run_sim.bat`** —— 结果直接显示在黑色窗口里，不生成 txt /
> xlsx 结果文件。

---

## 一、目录里有什么

| 文件 | 作用 |
|------|------|
| `run_sim.bat` | **双击入口**。提示输入模拟时长 + 随机种子，跑完把完整报告打印在窗口，并自动对比上一次结果 |
| `run_sim.py` | bat 调用的启动脚本，负责切到 `123/` 项目根、调 `simulate.py --stdout` |
| `simulate.py` | 模拟主程序。跑一次完整飞行、生成随机事件、逐 0.5s 喂给 `DroneAI`、产出时间轴 |
| `sim_last_fp.txt` | 唯一的状态文件：存"上一次运行的指纹"，供本次对比用。可删，删了下一次按"首次运行"处理 |
| `__init__.py` | 包标记，让 `drone_sim` 可被 import |

**结果不在这里**：bat 默认不写文件，报告直接打在窗口。想导出 xlsx 才需要
额外跑一条命令（见第四节）。

依赖：Python + `openpyxl`（决策引擎 `drone_ai` 要读 `Decision_Matrix.xlsx`，
需要它；bat 双击用的那个 Python 已装过，命令行环境若缺就 `pip install openpyxl`）。

## 二、怎么用（双击 run_sim.bat）

双击 `123/drone_sim/run_sim.bat`，窗口依次出现：

```
Sim minutes (default 8):      ← 模拟几分钟。直接回车 = 默认 8 分钟，也可输入如 4
Seed (blank=random):          ← 随机种子。回车 = 每次不同；输入数字 = 固定可复现
[Running] Simulating 8 minutes...
...（报告，见下节）...
[OK] Full report shown above. No result file written.
```

三个输入的含义：

- **时长**：模拟飞行的总分钟数。默认 8，可填 3 / 5 / 10……
- **种子**：随机数发生器种子。
  - **留空** → 每次跑都不一样（随机）
  - **填数字**（如 `42`）→ 同一数字结果完全可复现，方便"这次和上次到底变没变"对比
- 想连续看"不同结果"就每次留空；想验证可复现就填同一个数字连跑两遍。

## 三、怎么读报告（窗口里从上到下）

报告分四块，从上到下：

### ① 报告头 = 这次结果的"摘要"

```
本次指纹: events[lightning×1/propbreak×1/gps×2] modes[CRUISE=465s/PROTECT=47s/RTB=88s] changes=12
模拟 10 分钟 | 事件 8 个 | 指令变化 12 次
模式时长: CRUISE=465s, PROTECT=47s, RTB=88s
```

| 字段 | 含义 |
|------|------|
| `events[...]` | 这次随机注入了哪些异常、各几个。`wind×3`=大风 3 次，`lightning×1`=打雷 1 次 |
| `modes[...]` | 飞行中 AI 在各模式累计停留时长（秒） |
| `changes=N` | 整段飞行 AI 的指令一共变了 N 次（越小越平稳） |

**模式含义**：
- `CRUISE` 正常巡航
- `PROTECT` 保护无人机（避雨 / 防风 / 避雷 / 保机）
- `MISSION` 优先完成任务
- `RTB` 返航（Return To Base）

> 这一行指纹就是"每次不同"的核心证据：换种子，它必变。

### ② 事件列表 = 哪些突发状况、何时发生

```
#1  t=1m08s  打雷/雷暴线 (持续45s)
#5  t=1m40s  电调过热 (持续33s)
```
`#N  t=XmYs  事件名 (持续Zs)` = 起飞后第 X 分 Y 秒发生，持续 Z 秒。

### ③ 逐 tick 时间轴 = AI 怎么应对（最重要）

```
08:01:08  [W]  PROTECT | lightning  | dx=-4.29 dy=-4.29 (thunder=1 wind_speed=24.0) avoid_thunderstorm
08:02:17  [W]  RTB     | prop_break | dx=-4.47 dy=-4.47 (vib_high=1 esc_current=1.3) enroute_home
08:03:00  [OK]  任务完成 | 安全降落 | 共处理事件 8/8 个
```

逐列读法：

| 列 | 含义 |
|----|------|
| `08:01:08` | 模拟时刻（起飞 08:00:00 起算） |
| `[W]` | **异常触发行**（AI 对异常出的指令）。`[OK]`=事件开始/结束，`[CMD]`=普通巡航指令 |
| `PROTECT` | AI 切到的模式 |
| `lightning` | 触发的异常类型 |
| `dx=-4.29 dy=-4.29` | 指令内容。`dx/dy/dz`=NED 速度指令(m/s)，`dvyaw`=偏航角速度(deg/s)，`throttle_delta`=油门增量 |
| `(thunder=1 wind_speed=24.0)` | **触发它的传感器读数**——打雷 + 风速超阈值才动作 |
| `avoid_thunderstorm` | 这条指令的名字（升高离开雷暴） |

**怎么读懂**：`1:08 时打雷(雷声=1, 风速24) → AI 切 PROTECT、升高离开雷暴 + 水平远离。`
`( )` 里的读数就是"为什么此刻动作"的依据，不同种子下这些数字不同，
一眼能看出两次运行差别在哪。

### ④ 结尾 + 指纹对比

```
[last] events[gps×1/linkloss×1/lowbattery×1/wind×2] ... changes=8
[this] events[lightning×1/propbreak×1/gps×2] ... changes=12
[DIFF] different from last run  = output really changed
```
- `[last]` 上一次指纹，`[this]` 本次
- **`[DIFF]`** = 两次不同（换种子就能看到）；**`[SAME]`** = 两次相同（同种子重跑必然 SAME，正常）
- 末行 `共处理事件 N/N` = 全部异常都被 AI 处理完、安全降落（没坠毁）

```powershell

python drone_sim\simulate.py --minutes 8 --seed 42
```

每次运行覆盖重写（`_cleanup` 先删旧文件），不会残留混杂。

## 五、随机事件有哪几种（共 15 类，事件库扩充版）

模拟会随机注入 5~10 个事件（起飞/降落各留 30s 安全区不注），
事件类型池来自训练数据库 `Video_Action_DB_cleaned.xlsx`（6161 条视频），
覆盖 17 类 anomaly 中的 15 类可机载复现的异常：

### 原有 7 类

| 事件 | 叠加到传感器的量 | 典型 AI 反应 |
|------|------------------|--------------|
| 下雨 `rain` | rain=1 | PROTECT，回升到避雨高度（climb_rain_avoid） |
| 大风 `wind` | wind_speed 超阈值 | PROTECT，降高度（descend_wind） |
| 低电量 `low_battery` | battery_v/pct 拉低 | RTB，往 home 点真实返航（enroute_home / force_land） |
| 障碍 `obstacle` | obstacle_dist + bearing | 按方位角绕行（evasive，右前左转/左前右转） |
| 链路丢失 `link_loss` | link_ok=0, rssi=-100 | PROTECT 返航 |
| 鸟群 `bird` | bird_detect=1 | 偏航避让 |
| GPS漂移 `gps` | hdop 升高, sat 减少 | RTB 位置纠偏 |

### 新增 8 类（事件库扩充，2026-10-13）

| 事件 | 叠加到传感器的量 | 典型 AI 反应 |
|------|------------------|--------------|
| 打雷 `lightning` | thunder=1, wind_speed=24, rain=1 | PROTECT，升高离雷暴（avoid_thunderstorm） |
| 沙尘雾 `dust_fog` | visibility=5~40 | CRUISE（P=0.503），低速巡航 |
| 极端温度 `cold_hot` | temp_c < -10 或 > 55 | CRUISE（P=0.495），监控 |
| 电调过热 `esc_fault` | esc_temp=85~100 | RTB（P=0.628），返航 |
| 桨叶断裂 `prop_break` | vib_high=1, esc_current=0~1.5 | RTB（P=0.721），快速返航 |
| 电机失效 `motor_failure` | esc_current=0 | PROTECT（P=0.833），强制接管 |
| 载荷故障 `payload_fault` | obstacle_dist=2~5, gimbal_pitch=60~89 | MISSION（P=0.336），继续任务 |
| 云台故障 `gimbal_fault` | gimbal_pitch=85~95 | RTB（P=0.602），返航 |

电量随飞行线性下降、位置随速度漂移（模拟飞机真的在动），所以即使没注入
事件，巡航指令也会随时间小幅变化。

> 事件注入的 metric 值取自数据库里该 anomaly 类型实际视频的高频应对场景，
> 经 `trigger → P/T 校准矩阵 → combined_mode` 走完整机载链路，保证模拟出的
> "事件→决策→指令"链与真实训练数据一致，而不是随机堆数。

## 六、机载 AI 增强层（补强，2026-10-13）

`drone_ai` 包新增了两个增强模块，已在 `ai_main.tick()` 内部自动接入，
模拟器无需改动即生效：

### 1. 传感器滤波（`drone_ai/sensing.py`）

原始串口 metric 含噪声/跳变，直接进 `trigger.detect()` 会被误导。
三类轻量零依赖滤波器（O(1)，机载可跑）：

| 滤波器 | 用途 | 适用 metric |
|--------|------|------------|
| `ExponentialFilter` | 一阶低通，慢变量 | battery_v/pct、temp、esc_temp、wind、pressure、link_rssi、hdop、visibility |
| `MedianGate` | 中值门控+MAD，抑制单帧尖峰 | esc_current、obstacle_dist |
| `Kalman1D` | 匀速卡尔曼，连续量 | position、speed |

接入点：`ai_main.tick()` 第 1 步 `metrics = self.sens.update(raw_metrics)`，
之后 `trigger.detect(metrics)` 用的是整形后的值。

### 2. 指令平滑（`drone_ai/smooth.py`）

飞控指令逐周期突变会导致机臂抖动/振荡。`CmdSmoother`：
- 每轴斜率限制 + 可选一阶低通
- **PROTECT/RTB 快速模式放宽 3 倍斜率**（保机要快），普通模式收紧
- 异常类型切换时重置 smoother，避免上轮指令残留压死新指令

接入点：`ai_main.tick()` 第 6-7 步，在 `_clamp_cmd` 之前。

### 效果（在模拟输出中可辨识）

看 Timeline 的指令数值，平滑已经生效——RTB 的水平速度不再每 tick 顶到满值，
而是**逐步逼近**（rate-limiter 起作用的证据）：
- `battery_issue ... dx=-4.53 dy=-4.53 [enroute_home]`：P 联动缩放
  （`protect_strength`）把满速 8 m/s 压到 ~5 m/s 档，再由斜率限制器平滑爬升。
- 同一模式切换前后指令是**渐进过渡**（`-0.23 → -0.67 → -0.84 → -1.10`），
  而非阶跃跳变，这正是 `CmdSmoother` 的机臂防抖效果。

## 七、常见问题

- **双击 bat 报 `No module named 'openpyxl'`**：那个 Python 没装 openpyxl。
  `pip install openpyxl` 后重试。
- **两次结果看着一样**：正常。指令值由巡航积分 + 固定限幅决定，不同种子
  常收敛到同串数。**盯报告头指纹行和结尾 [DIFF]/[SAME]**，那里最能体现
  两次差异（事件分布 / 模式时长 / 指令变化次数不同）。
- **想固定复现某次结果**：两次都填同一个种子数字，指纹会完全一致（[SAME]）。
- **想删掉"上次指纹对比"**：删除 `drone_sim\sim_last_fp.txt`，下次按首次运行处理。
- **新增事件不触发**：检查 `drone_ai/trigger.py` 的 `TRIGGER_RULES` 是否包含
  对应 metric 的判定规则（如 `thunder → lightning`），以及 `drone_ai/serial_io.py`
  的 `CHANNELS` 是否声明了该 metric。
- **自身事件终止了任务**：报告出现 `[CRIT] 任务终止 | 自身事件[xx] 立即就近迫降`
  及 `飞行提前终止 ... 任务未正常完成` 属正常——这是 2026-10-13 新增的底层限制，
  命中 7 类自身事件（电机失效/飞控死机/电池故障/桨叶断裂/电调过热/云台故障/载荷故障）
  时 AI 立即就近迫降并终止任务，后续注入事件不再处理（详见第六节"自身事件"）。

## 八、自身事件 · 立即迫降 + 任务终止（底层限制，2026-10-13）

### 背景
原有 15 类事件里，既有"外部因素"（雨/风/GPS/障碍/鸟/链路/打雷——AI 走 RTB 返航，
任务可继续），也有"无人机自身故障"（机体/动力/飞控/电池/电调/桨/云台/载荷内部损坏）。
本次底层加了一条硬限制：**自身事件一旦命中，立即就近迫降 + 终止任务**，
不再返航 home、不继续巡航、后续事件不再处理。

### 自身事件白名单（7 类，DroneAI.SELF_FAULT_TYPES，与 decision.SELF_ABORT_TYPES 同源）

| 事件 | 触发 metric | 含义 |
|------|-------------|------|
| `motor_failure` | esc_current≤0 | 电机失效 |
| `flight_ctrl` | flight_ctrl_alive=0 | 飞控死机/复位 |
| `battery_issue` | battery_v<14.4V 或 battery_temp>65°C | 电池过低/过温 |
| `prop_break` | vib_high=1 | 桨叶断裂 |
| `esc_fault` | esc_temp>80°C | 电调过热 |
| `gimbal_fault` | gimbal_pitch 异常 | 云台故障 |
| `payload_fault` | 载荷相关 metric | 载荷故障 |

### 迫降指令（_force_land_abort）
命中自身事件时 AI 强制下发：
- 水平速度收敛 dx=dy=0（稳着落，不冲 home）
- 强下降 dz=3.0 m/s（RTB_DESCENT_MPS×1.5，比低电迫降更快）
- 偏航收敛 dvyaw=0
- 油门收敛 throttle_delta=-0.3（防动力故障拉高油门恶化）
- 清除 RTB/模式动作残留字段，标记 `force_land=self_fault_force_land`
- 置 `task_aborted=True` + 记录原因/时刻，模拟器据此终止飞行

### 决策层同步（2026-10-13，AI 算法原生识别自身事件）
除上述 ai_main 层迫降指令外，本次把终止判定下沉到 `drone_ai/decision.py` 决策层，
使 AI 算法本体原生产生终止模式 `FORCE_LAND`，不再只靠模拟层事后检查 task_aborted：
- 新增 `SELF_ABORT_TYPES`（7 类自身事件）+ `is_self_fault(anomaly)` 判定函数
- `combined_mode()` 开头"自身事件一票否决"：命中任一自身事件 → 直接返回 `FORCE_LAND`
- `ModeSelector.pick_mode()` / `action_for()`：自身事件 → `FORCE_LAND` 模式 + 动作"立即就近迫降并终止任务"
- `should_rtb()`：自身事件改判 False（不返航 home，就近迫降终止）
- `ai_main.DroneAI.SELF_FAULT_TYPES` 改为引用 `decision.SELF_ABORT_TYPES`（单一来源，避免双份维护）
- `tick()` 第 5.5) 段：`mode==FORCE_LAND` 或 atype 命中白名单（双保险）即触发迫降终止；
  `smoother` 快速模式纳入 `FORCE_LAND`；`_force_land_abort` 把 `cmd[mode]=FORCE_LAND` 写回

### 模拟报告里的识别
正常完成与提前终止的结尾行不同：
- 正常：`[OK] 任务完成 | 安全降落 | 共处理事件 N/N 个`
- 自身事件终止：`[CRIT] 任务终止 | 自身事件[xx] 立即就近迫降 | 后续事件不再处理`
  紧跟 `[CRIT] 飞行提前终止 | 自身事件[xx] 迫降 | 已处理事件 K/M | 任务未正常完成`
  （K<M 即有事件被跳过未处理）。报告头指纹的 `modes[...]` 会出现 `FORCE_LAND` 项（AI 决策层原生产生的终止模式）

## 十、路线判断 / 避障 / 行为动作 全走 drone_ai 算法（闭环，2026-10-13）

此前模拟器的位置是写死的 `ts*0.01` 线性漂移、障碍方位角是随机注入的，
只有"行为动作选定（模式/动作）"走了 drone_ai 决策层。本次把用户要求的
三件事——**路线判断、避障、行为动作选定**——全部下沉到 drone_ai 算法，
并把模拟器改成**闭环**（无人机真的按 AI 返回的指令飞）：

| 三件事 | 用 drone_ai 哪个算法 | 在报告里怎么认 |
|--------|---------------------|---------------|
| **路线判断**（往哪飞） | `drone_ai/route.py`：`RoutePlanner`（多 waypoint 选下一航点）+ `route_velocity`（航线速度向量） | 时间轴 `[OK] 航线完成 \| 已飞完 N 个 waypoint，返航 home`；指令 `dx/dy/dz` 随航线变化 |
| **避障**（怎么躲） | `drone_ai/obstacle.py` `avoid_obstacle`，方位角由 `route.obstacle_bearing` 从"无人机当前位置 + 机头朝向 vs 障碍位置"几何算出（不再随机） | 时间轴 `[W] CRUISE/PROTECT \| obstacle \| ... dvyaw=±30 ... evasive/turn`，括号里 `obstacle_dist=... bearing=...` |
| **行为动作选定**（选什么模式/动作） | `drone_ai/decision.py`：`combined_mode`（P/T 双值）+ `action_for`（查策略库出动作），自身事件一票否决 `FORCE_LAND` | 时间轴 `[W] RTB \| wind_gust ...` / `[CRIT] FORCE_LAND \| prop_break ... 任务终止` |

### 闭环怎么工作

模拟器每个 tick：
1. 把当前 `self._pos`（NED 位置）/ `self._yaw`（机头朝向）+ 注入事件 喂给 `DroneAI.tick()`
2. AI 返回 `dx/dy/dz/dvyaw`（路线速度 + 避障转向 + RTB 返航速度）
3. 模拟器把指令**积分**回 `self._pos` / `self._yaw`（`pos += v*dt`，`yaw += dvyaw*dt`）
4. 下一 tick 用新位置/朝向再喂 AI —— 所以无人机真的沿航线飞、真的转向避障、真的返航，而不是写死漂移

### 新增文件 / 字段
- `drone_ai/route.py`（新增）：`RoutePlanner` / `route_velocity` / `obstacle_bearing` / `default_waypoints`
- `DroneAI.__init__(..., route_waypoints=None, home=...)`：传 `route_waypoints` 启用多航点路线判断；不传退回单点定点（向后兼容）
- `serial_io` 的 `uart4` 新增 `obstacle_pos`（NED [x,y,z]）metric：避障几何方位角的输入
- `cmd` 新增 `route_wp` / `route_return` / `route_event` 字段：标记当前航点、是否返航段、航点到达事件

`t=38s` 出现"航线完成"（路线判断）；`t=53s` obstacle → evasive `dvyaw=-30`（几何避障）；
